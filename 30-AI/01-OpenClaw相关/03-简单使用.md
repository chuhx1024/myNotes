## user

安装完成了 接下来 怎么使用呢

## assistant

安装成功只是第一步，现在的 OpenClaw 就像一个刚装好系统的电脑，虽然能运行，但还没“干活”的能力。

既然你是前端程序员，我们直接跳过那些繁琐的基础介绍，进入“开发者模式”。接下来的步骤是：启动服务 -> 验证核心能力 -> 安装 Skills（插件） -> 实战。

🚀 第一步：启动服务 (Gateway)

OpenClaw 的核心是一个本地网关，你需要先把它跑起来。
启动命令
    在终端输入：
    openclaw gateway start
    注意：不要关闭这个终端窗口，它是服务端。如果你想让它后台运行，可以使用 openclaw gateway start --daemon。
获取访问地址
    启动成功后，终端会输出一段日志，其中包含一个本地 URL，通常长这样：
    http://127.0.0.1:18789/?token=你的访问令牌
    
    复制这个链接，在浏览器（Chrome/Edge/Arc）中打开。这就是你的 OpenClaw 仪表盘 (Dashboard)。

🛠️ 第二步：安装“手脚” (Skills)

刚装好的 OpenClaw 只能陪你聊天。要让它能操作文件、读写数据，必须安装 Skills。这就像给浏览器装扩展程序一样。

推荐使用官方命令行工具 clawhub（类似 npm）：
安装 ClawHub (如果还没装)
    npm install -g clawhub@latest
安装前端/程序员必备技能
    在终端执行以下命令，安装几个高频实用的技能：
文件管理 (file-manager)：让它能读写、整理你的本地文件。
浏览器自动化 (agent-browser)：让它能打开网页、抓取数据（需配合浏览器扩展）。
代码/数据处理 (code-interpreter 或 file-processor)：处理 Excel、CSV 或简单代码逻辑。

    一键安装命令：
    clawhub install file-manager agent-browser
    (安装完成后，在 Web 仪表盘的“技能管理”中可以看到它们已启用)

💻 第三步：实战演练 (前端视角)

现在，回到浏览器的 Dashboard 界面，试着发送指令。作为前端，你可以从以下几个场景开始“调教”它：

场景 1：文件操作 (验证权限)
不要只问问题，让它动手。
指令： “帮我在桌面上创建一个名为 OpenClaw_Test 的文件夹，并在里面创建一个 hello.md 文件，内容写‘Hello OpenClaw’。”
预期： 去桌面看一眼，文件夹和文件应该已经生成了。

场景 2：代码/文件处理 (发挥特长)
假设你有一个包含很多杂乱代码的文件夹，或者一个巨大的 JSON 文件。
指令： “读取当前目录下的 package.json，帮我检查一下有没有过时的依赖包，并列出它们的名称。”
指令： “帮我把 src/components 目录下所有的 .js 文件重命名为 .jsx。”

场景 3：浏览器自动化 (联网能力)
指令： “打开 GitHub 的 Trending 页面，抓取今天排名第一的项目名称和 Star 数，发给我。”
注意：首次使用浏览器技能时，可能需要按照提示在 Chrome/Edge 中加载一个扩展程序（Browser Relay），按屏幕提示操作即可。

⚙️ 第四步：进阶配置 (像配置 .env 一样)

作为开发者，你可能想自定义配置，而不是每次都通过向导。
配置文件位置
    核心配置文件通常在：~/.openclaw/openclaw.json 或 ~/.openclaw/config.json。
    你可以用 VS Code 打开它：
    code ~/.openclaw/config.json
修改模型
    如果你想切换模型（比如从 GPT-4 换到 Claude 3.5 或 Kimi），直接在这个 JSON 文件里修改 model 字段和 apiKey 即可，然后重启网关：
    openclaw gateway restart

🛡️ 安全提示 (重要)
权限控制：OpenClaw 拥有你当前用户的文件读写权限。不要以 sudo 身份运行它。
指令审查：在执行删除文件、覆盖代码等高风险操作前，OpenClaw 通常会在 Web 界面请求你的确认（Approval），请务必看一眼它准备执行的 Shell 命令是什么。

现在，去 Dashboard 试着下达你的第一条指令吧！如果遇到报错，直接把终端的 Log 发给我。
