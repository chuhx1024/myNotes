🦐 OpenClaw 核心档案

一句话定义：
OpenClaw 是一个开源的、本地优先的 AI 智能体（Agent）框架。它不只是一个聊天机器人，而是一个拥有“手脚”的数字员工，能够通过安装插件（Skills）来操作你的电脑、浏览器和应用程序。

核心隐喻：
如果把你的电脑比作一个前端项目，OpenClaw 就是运行时（Runtime），而各种功能插件就是 npm 包（Skills）。

🏗️ 技术架构 (前端视角)

OpenClaw 的设计非常模块化，你可以这样理解它的架构：
Gateway (网关/服务层)
这是核心守护进程，负责维持长连接、管理内存和上下文。它就像一个 Webpack Dev Server，一直在后台运行，监听指令。
Agent (核心逻辑层)
这是“大脑”。它接入各种大模型（GPT-4, Claude, 文心等），负责理解你的自然语言，并将其拆解为具体的任务规划。
Skills (技能/插件层)
这是“手脚”。每一个 Skill 都是一个独立的脚本或 npm 包（如文件读写、浏览器控制、代码执行）。Agent 通过调用这些 Skills 来对操作系统产生实际影响。
Memory (记忆/状态层)
本地数据库（SQLite/Vector DB），用于存储你的个人习惯、历史对话和长期偏好，实现“养成感”。

🚀 核心能力与差异化
特性 | 传统大模型 (ChatGPT/Claude) | OpenClaw
:--- | :--- | :---
工作模式 | 被动问答 (你问它答，说完即焚) | 主动代理 (你下指令，它后台执行，长期驻留)
操作权限 | 沙盒内 (无法触碰你的文件系统) | 系统级 (可读写文件、控制鼠标、操作终端)
记忆能力 | 短期 (仅限当前对话窗口) | 长期 (跨会话记忆，越用越懂你)
数据隐私 | 云端 (数据上传至厂商服务器) | 本地 (数据留存在自己电脑，支持离线)
⚠️ 风险与争议 (必读)

虽然功能强大，但 OpenClaw 目前仍处于“狂野西部”阶段，存在显著风险：
权限过大：它拥有你电脑的最高操作权限。如果 Prompt 被注入攻击，或者 AI 产生幻觉，它可能会误删文件、清空邮箱或执行恶意代码。
隐私泄露：虽然本地部署相对安全，但一旦接入云端大模型 API，敏感数据（如代码、文档）仍会经过第三方服务器。
不可控性：作为自主智能体，它在执行复杂任务时可能会出现“死循环”或偏离预期的行为。

📅 发展简史
2025.11：项目前身 Clawdbot 发布，最初只是一个 WhatsApp 消息中继器。
2026.01：因商标问题更名为 Moltbot，随后定名 OpenClaw。因“自主买车”、“自动写代码”等演示视频在 GitHub 爆火。
2026.02：腾讯云、阿里云、百度智能云等大厂相继推出“一键部署”服务，国内用户量激增。
2026.03：国家互联网应急中心发布风险提示，提醒用户注意系统级权限带来的安全隐患。
