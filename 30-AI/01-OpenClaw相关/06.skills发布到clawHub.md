发布 OpenClaw Skill 和发布 npm 包在流程上几乎一模一样，但在“审核机制”和“元数据描述”上有一些独特的“坑”。

你可以把 ClawHub（OpenClaw 的官方市场）理解为 “npm + App Store 审核机制” 的结合体。

以下是发布 Skill 的完整“前端化”流程：

📦 第一阶段：打包准备 (像写 npm 包一样)

就像 package.json 是 npm 包的核心，Skill 的核心是 SKILL.md。
规范命名
    你的项目文件夹名和 package.json 中的 name 必须以 openclaw-skill- 开头。
✅ 正确：openclaw-skill-git-stats
❌ 错误：my-cool-tool
编写 SKILL.md (关键！)
    这是 AI 的“说明书”。npm 包看 README.md，OpenClaw 看 SKILL.md。
Frontmatter (元数据)：必须包含 name, description, version。
Use when / NOT for：这是 AI 判断“什么时候调用这个技能”的依据。写得越清晰，AI 调用越准。
Workflow：告诉 AI 具体怎么执行（调用哪个脚本，传什么参数）。
依赖管理
    在 package.json 里写清楚依赖。注意，尽量保持轻量，不要引入巨大的二进制文件，否则用户安装会很慢。

🚀 第二阶段：发布流程 (命令行操作)

这一步和你发 npm 包完全一致：
登录 npm
    npm login
版本号管理
    npm version patch  # 1.0.0 -> 1.0.1 (修个 bug)
    # 或者
    npm version minor  # 1.0.0 -> 1.1.0 (加个功能)
推送到 npm 仓库
    npm publish
    此时，你的代码已经存在于 npm  registry 上了。用户理论上可以通过 npm install 安装它，但 OpenClaw 的商店里还搜不到。

🛒 第三阶段：上架 ClawHub (像提交 App Store)

这是和 npm 最大的不同点。代码在 npm 上，但索引在 ClawHub。你需要去 ClawHub 官网“注册”你的包。
访问 ClawHub 官网
    去 ClawHub 的开发者后台（通常是 clawhub.com/submit 或类似入口）。
关联 npm 包
    输入你刚才发布的 npm 包名（如 openclaw-skill-git-stats）。系统会自动拉取你的 package.json 和 SKILL.md 信息。
填写展示信息
图标：上传一个好看的 Logo。
截图：展示技能运行时的效果。
分类：选择是“生产力”、“开发工具”还是“娱乐”。
提交审核

🛡️ 第四阶段：审核与避坑 (最难的一关)

npm 是“先发布后审核”（甚至不审核），但 ClawHub 是“先审核后上架”。作为前端程序员，你最容易在以下几个地方被拒：
权限等级乱标 (高危)
**坑**：你的技能只是读取文件（只读），但你标了“系统执行”权限。
**解**：严格遵守权限分级。只读标 1 级，写入标 2 级，执行 Shell 命令标 3 级。乱标会被直接打回。
SKILL.md 描述不清
**坑**：没写清楚 Use when，导致 AI 在该调用的时候不调用，或者不该调用的时候乱调用。
**解**：用自然语言把触发场景写得非常具体。
缺少异常处理
**坑**：网络断了、文件不存在时，脚本直接崩溃（Crash）。
**解**：所有外部调用必须加 try-catch，并返回友好的错误 JSON。
跨平台兼容性
**坑**：你在 Mac 上写的脚本用了 osascript，结果 Windows 用户装了直接报错。
**解**：要么做系统判断兼容，要么在描述里写清楚“仅支持 macOS”。

🔄 总结：npm vs OpenClaw Skill
步骤 | npm 包发布 | OpenClaw Skill 发布
:--- | :--- | :---
代码核心 | index.js / lib/ | SKILL.md (逻辑描述) + script (执行代码)
配置文件 | package.json | package.json + plugin.json (可选)
仓库 | npm Registry | npm Registry (存代码) + ClawHub (存索引)
安装命令 | npm install xxx | clawhub install xxx
审核机制 | 无/宽松 | 严格人工审核 (1-3 个工作日)
更新方式 | npm publish | npm publish + ClawHub 自动检测更新
一句话建议：
既然是前端，就把 Skill 当作一个“带严格代码审查的开源组件”来写。代码写得再溜，如果 SKILL.md 写不好，AI 也理解不了你的意图，审核也过不了。
